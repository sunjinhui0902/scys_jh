# 方法、核验与维护

## 按项目目标复用

服务历史文化、城市观察与图书内容：一个具体疑问进入，两个到三个必要事实支撑，一个可见发现收束，再自然引到实际图书。事实来源留后台，不把核对过程念进口播。

- [参考图书到视频号 Skill](../../../.agents/skills/reference-book-to-video/SKILL.md)：检索、回原页、写稿和证据边界。
- [视频号图书内容 Skill](../../../.agents/skills/wechat-channels-book-commerce/SKILL.md)：口播、分镜、商品衔接及发布检查。
- [GitHub技能选型与复用记录](../../参考图书拆解_2026-10-15/04_GitHub技能选型与复用.md)：保留首轮选型结果，外部仓库状态与许可不因本次归档重新确认。
- [说书式口播写法](../../07_说书式口播写法.md)：项目现有方法；归档时工作区文件，维护与同步由原任务负责。
- [短片生产SOP](../../03_短片生产SOP.md)、[发布复盘表](../../04_发布复盘表.csv)：沿用现有生产与反馈入口。

## 核验优先级

先处理实际稿件会使用的事实、数字和画面。差异项保留原口径；未确认的细节可避用。参考[来源与核对说明](../../15城专题拆解_2026-10-15/来源与核对说明.md)。研究书目、实际售卖SKU和素材许可分别记录。

## 新资料怎样存

1. 新书或新城市拆解另开带日期批次，保存书目指纹、读取范围、事实与候选题；已验收原件不覆盖。
2. 扩展 `scripts/build_reference_knowledge.py` 的明确来源，更新此分类入口和检索索引；不扫描OCR全文、不自动吸收未经审核的生产稿。
3. 用 `--check` 验证索引与源记录一致，再按项目约定只同步该次任务结果。原PDF、OCR全文、页面图和媒体遵循各自存储约定。
4. 新开场、完整稿、配音、成片、发布与反馈分别计数；只有实际数据支持时才归纳表现。

本次只增加知识库分类、检索和路由，没有改变原批次事实状态、竞品验收数量或既有试做工程。
