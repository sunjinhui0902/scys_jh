# 阅见生活｜竞品视频分析与图书带货原创模板提炼

**终版执行计划书 V4.0｜2026-10-14**  
**执行方式：Codex（本地数据处理与总控）＋ Antigravity，简称 A（Gemini 内容理解）＋ 人工阶段验收**  
**适用阶段：已批量下载竞品视频，尚未建立内容分析与原创生产流程**

> **一句话目标**：盘点约 317 条下载记录，批量提取真实视频中的文案与视觉样式，寻找跨账号反复出现的选题、书籍和带货话术，再从有依据的代表视频中总结可供「阅见生活」使用的**原创**脚本模板。先跑通分析，不开发大而全的平台。

## 1. 输入、范围与边界

### 1.1 已知素材

当前截图包含 **6 个账号目录**：

- 锦绣千秋录
- 开卷读书
- 林睿读书&书在橱窗
- 破局书屋
- 文汇书香苑
- 赵健的读书日记

另有 `records.db`、`records.db-shm`、`records.db-wal`，疑似下载工具使用的 SQLite 数据库及其辅助文件。用户估计**约 317 条记录**，这**不等于 317 个可解码的视频文件**。实际文件总数、成功下载数、重复数、唯一内容数必须由 Codex 实测，不能预先填固定值。

启动前唯一必须补齐的业务信息是：**包含上述目录的本地绝对路径 `VIDEO_DIR`**。如已有既定输出路径，沿用；否则在原素材目录之外创建独立 `OUTPUT_DIR`。不得擅自扫描整个硬盘。

### 1.2 核心业务问题

1. 六个账号分别在讲哪些书、人物、故事和生活问题？
2. 哪些**书名、选题、开头钩子、故事桥段**在同账号/跨账号出现频繁？
3. 视频怎样实现「吸引注意 → 情绪共鸣/认知冲突 → 故事或观点 → 引出书籍 Bridge → 价值理由 → 促单 CTA」？
4. 主要视觉形式是翻书实拍、真人口播、AI 素材混剪、文字卡片还是混合？
5. 哪些可抽象成 **3～8 套原创图书内容模板**，供后续本地剪映自动化生产？模板不足时不凑数。

### 1.3 明确不做

- 不重新爬取平台，不为本任务部署 MediaCrawler、VideoAgent、PySceneDetect、n8n、数据库服务或可视化平台。
- 不对 317 条视频全部做逐镜头深度分析；**全量做基础处理，精选 20～30 条做深度 AI 分析**。
- 不自动发布、搬运、复刻他人的完整文案、声音、视频画面或受版权保护的素材。
- 不在缺少点赞、播放、转发、商品点击、成交数据时宣称“爆款已验证”“转化率高”“真实销量好”。重复使用只说明**值得研究的候选模式**。
- 不默认 Gemini API，也不让 Codex 绕过 Antigravity 官方输入方式、额度、登录与授权限制。

## 2. 最终产出与技术栈

### 2.1 最小工具配置

| 工作 | 负责人 | 首选工具 | 原则 |
|---|---|---|---|
| 扫描/核对/去重/断点续跑 | Codex | Python 标准库、SQLite（如有必要） | 源文件只读，断点可恢复 |
| 视频元数据、音频提取与固定截图 | Codex | FFmpeg / ffprobe | 每条默认 4 张，不做全量分镜 |
| 中文口播转写 | Codex | [FunASR](https://github.com/modelscope/FunASR) + Paraformer 中文模型；按需配置 VAD/标点 | 先用 10 条验证书名、人名和古诗词；不预装两套 ASR |
| 相似度与高频统计 | Codex | Python + 轻量字符 n-gram / TF-IDF（按需安装依赖） | 文案相似≠同书≠文件重复，分开统计 |
| 文本/截图/视频深度理解 | Antigravity | 现有 Gemini 模型能力 | **不申请 API Key**；能否直读 MP4 必须实测 |
| 数据汇总与验收 | Codex | JSON / openpyxl | 一个 Excel、7 个 Sheet，保存证据源 |
| 后续内容制作 | 后续阶段 | 现有剪映自动化 | 本计划不进入正式量产 |

**重要说明**：Antigravity 安装在本机并不代表 Gemini 是离线本地模型；材料可能被发送至云端。第一次提交外部模型前，明确用户准许的范围（文字、截图或原视频）以及使用额度。没有 API Key 并不意味着零消耗或无限次数。

### 2.2 统一交付物

- `阅见生活_竞品视频分析_终版.xlsx`：**一个**工作簿、7 个 Sheet。
- `reports/素材盘点报告.md`、`reports/10条样本验收.md`、`reports/高频复用与候选清单.md`、`reports/最终验收报告.md`。
- 每条视频的 `video_id`、源路径、转录 TXT、带时间戳 JSON、4 张基础图片及阶段状态。
- 经 A 分析后的**单视频结构化 JSON**；账号级总结与跨账号规律；3～8 套有证据支持的原创模板。
- `README.md`：可复制的执行、恢复、交接、重跑、导出命令。

## 3. 两个 Agent 的先后顺序（必须执行）

**顺序：Codex 启动 → 10 条样本与 2 条 MP4 能力测试 → 用户验收 → Codex 全量基础处理、A 分析已就绪样本（可并行） → Codex 生成 20～30 条候选 → A 深度分析 → Codex 汇总验收。**

| 时点 | Codex 要做的事 | A 要做的事 | 是否需要等待 |
|---|---|---|---|
| T0 | 素材盘点、检测环境、挑选 10 条样本 | 暂不启动 | A 等待至少 2 条就绪的样本 |
| T1 | 完成 10 条 ASR、截图、报告 | 用其中 2 条验证能否真正听懂/看懂 MP4；另以文字+截图验证备用方式 | 两边可在样本就绪后交叉进行 |
| **关口 G1** | 呈交样本质量、估算全量耗时 | 呈交 MP4 能力证明、输入方式与可能的上传范围 | **用户确认后再全量推进** |
| T2 | 全量转录、抽帧、初步去重 | 先分析已就绪的 3～5 条，校准结构化字段及提示词 | **可并行，不共享写入同一文件** |
| T3 | 完成全量重复度分析，推荐 20～30 条并封装交接包 | 读取确认完成的交接包，分批分析、持续落盘 | A 的大规模深度任务等候候选清单 |
| T4 | 校验 A 的 JSON、汇总 Excel、编写 QA | 对缺证据或冲突结果做复核 | **A 当前批次结果落盘后，Codex 才导入该批** |
| T5 | 最终验收、交付、冻结本次结果 | 不再改动已验收数据 | Codex 最后结束 |

**协作规则**：

- Codex **独占写入** `manifest/`、`transcripts/`、`frames/`、`clusters/`、`reports/` 和最终 Excel；A 仅**独占写入** `analysis_a/`。
- Codex 每次生成完整 `handoff/<video_id>/` 后，最后原子写入 `READY.json`。A **仅处理存在 `READY.json` 的交接包**，不得读正在写入的文件。
- A 的结果先保存为临时文件，验证为合法 JSON 后原子重命名为 `analysis_a/<video_id>.json`，Codex 只导入完整文件。不得两个 Agent 同时修改同一份 Excel、manifest 或 JSON。
- 不假设 Codex 能自行启动、控制或调用 A。没有官方支持的集成方式，就由用户在两个 Agent 间**复制任务指令，共享目录传递结果**；无需开发自动中转服务。

## 4. 分阶段工作内容

### Phase 0｜素材核对与环境检查（Codex）

1. 读取用户给出的 `VIDEO_DIR`，递归识别 MP4、MOV、M4V、MKV 等视频；**非视频数据库文件不能计作有效视频**。
2. 输出：视频文件数、可解码数、无音轨数、损坏数、账号文件数、文件大小、总时长、尺寸、编码信息。
3. 对完全重复文件做 SHA-256 校验并保留**所有来源路径和账号映射**；内容相似但编码不同的文件在后续文案聚类处理。
4. 如果 `records.db` 含作者、平台标题、视频 ID、原链接、发布时间或互动数据，可以在保证 SQLite 一致性的前提下**只读检查其表结构与字段**，并按可靠键关联视频。若下载器正在写入，应避开不安全的直接复制或改写 `db`/`-wal`/`-shm`；优先 SQLite 在线备份或只读访问。不能假设数据库一定含播放量和销量。
5. 记录 Python、FFmpeg、FunASR 是否已安装，以及 CPU、内存、GPU、磁盘剩余空间。复用现有环境，不重复装不必要的依赖。
6. 输出 `manifest.jsonl` 和盘点报告；账号无法从路径可靠解析时标记“未知”。

**验收 G0**：源目录每个支持的视频文件在清单中恰好有一条路径记录；异常仍保留；账号小计与总计可对账；原文件未变化。

### Phase 1｜10 条样本试运行（Codex）＋ 2 条视频能力验证（A）

**Codex：**

1. 选 10 条覆盖 6 个账号（有文件的账号至少一条），兼顾时长与不同画面类型。
2. 使用 FFmpeg 抽音频，FunASR 生成 `transcript.txt`、`segments.json`；校验分段时间戳、空音频、重复幻觉和长视频拼接。
3. 每条默认取 **1 秒、5 秒、50% 进度、倒数第 2 秒** 四帧；极短视频自动限界、去重并记录实际时间，不取超出长度的时间戳。
4. 人工抽查每条视频**开头、书名/人名/成语、引书段落、结尾**；标记专有名词问题，建立可修订的书名别名词典。不要预设识别率或处理时长。
5. 记录真实样本运行时长、视频总分钟数、处理速度系数；据此估计全量任务时间和磁盘需求。

**Antigravity：**

1. 用上述样本中的 2 条不同类型 MP4，按**当前产品实际支持**的方式测试是否能够理解完整声音和画面。
2. 核对四项：指定秒数的画面、准确口播内容、第一次提及书籍时间、末尾是否出现购买引导。只能读到路径、元信息或缩略图时，**不得判定完整视频理解成功**。
3. 若 MP4 不可用，采用 `transcript.txt + frames/*.jpg`；此模式不可声称已经识别完整音乐节奏或全部镜头。可按引书/CTA 时间追加帧。
4. 输出 `MP4能力验证.md`，标记 `native_video`、`text_plus_frames` 或 `text_only`，不虚构模型输入方式。

**验收 G1（用户确认）**：10 条样本有可核验文本与截图；书名、人名和重要桥段不存在系统性错误，若有则先修正规则；A 的输入能力与潜在云端素材传输范围得到明确确认。未过关不得直接全量跑。

### Phase 2｜全部视频本地基础处理（Codex）＋ A 小批量试标注

**Codex：**

1. 对全部可处理视频提取转录文本、时间戳、4 帧截图；无语音/纯音乐/损坏另列状态，不伪造文案。
2. 每条完成一个步骤就原子写入独立状态 JSON，记录错误原因、工具版本、耗时与重试次数；`--resume` 时跳过已成功步骤，失败有限重试。
3. 完全重复文件可复用转录结果，但不同账号来源不能被吞掉。
4. 先做轻量文字清洗、同书别名归一，再执行三类**互不混淆**的统计：
   - **文件完全重复**：SHA-256 一致；
   - **口播相似**：开头相似、全文相似、故事段落相似；
   - **选题重合**：同一本书、人物或典故被多个视频/账号提及。
5. 标识“**提及一本书**”“**明确推荐一本书**”“**出现商品/购物引导**”，不能全部当作在销售该书。
6. 每个重复簇记录 `cluster_id`、视频 ID 列表、涉及账号数、样本引文和相似度依据；让人工可复核。
7. 候选样本选取不能简单按重复数量排名。建议 20～30 条覆盖：跨账号高频、同账号反复改稿、不同账号特色、高频书籍、强/弱 Bridge 与 CTA，以及少量低频对照。

**Antigravity：**

- 可在 Codex 全量运行时，先读取已 `READY` 的 3～5 条试做业务结构化分析，校准字段和证据格式。
- 正式深度分析 20～30 条的主清单须待 Codex 完成重复聚类、候选排序后再确定，避免误选。A 处理过程中随时落盘，不等全批次结束才保存。

**阶段输出**：全量基础处理清单、`高频复用与候选清单.md`、所有转录与截图、待 AI 分析交接包；即使 A 暂不可用，Codex 仍可以导出**基础版 Excel**，AI 字段标 `AI_PENDING`。

### Phase 3｜图书带货深度拆解与原创模板（A 主导）

**默认深度分析 20～30 条代表视频**；其余视频保留基础数据与候选标签。若 A 实际额度、输入能力不足，减少深度数量并客观报告，不得把 `AI_PENDING` 计入完成。

每条视频要求输出以下字段：

| 分类 | 核心字段 |
|---|---|
| 身份与来源 | `video_id`、账号、原路径、实际输入模式、分析时间、可用证据 |
| 选题与书籍 | 主题、分类、提及书名、**实际推荐书名（不确定填未知）**、历史人物/故事、受众画像（推断标注） |
| 开头 | **0～3 秒真实口播**、前三句话、Hook 类型（悬念/痛点/反常识/金句/轶事）、发生时间 |
| 叙事 | 主要矛盾/痛点、情绪变化、故事推进结构、知识或情感价值 |
| **引书 Bridge** | **从故事过渡到图书推荐的原文、时间点、转折方式**；不存在要明确填“无” |
| **转化 CTA** | **促单原话、时间点、类型**（软推荐/点击商品/价格锚点/稀缺性等）；没有则填“无” |
| 产品价值 | 书籍能带来的价值主张；区分视频明确声称与 AI 推断，**不编造功效或价格** |
| 画面/声音 | 画面类型、封面展示、字幕样式、背景音乐/配音特征；只有文本+4帧时无法完整判断的字段留空 |
| 重复证据 | cluster ID、同账号重复数、跨账号数、参考视频 ID |
| 可复用结构 | 抽象的开头公式、叙事框架、自然引书方法、CTA 结构、原创选题建议与版权风险 |

**注意**：0～3 秒可能没有语音，因此必须区分**音频钩子**与**视觉钩子**；不能把整段前三句话当作真实发生在前 3 秒。重要摘录保留实际时间范围，不以长篇复制竞品文案作为交付重点。

**模板交付**：归纳有证据的 **3～8 套模板**，每套含适用目标受众、主题范围、开头/故事/Bridge/CTA 结构、建议时长、视觉形式、示例原创选题、参考 video_id、相似性与版权风险。原创成稿需在下一阶段另行生产，不在本次批量复制竞品脚本。

### Phase 4｜Codex 最终整合、Excel 与验收

仅生成一个 `阅见生活_竞品视频分析_终版.xlsx`，包括以下 7 个 Sheet：

| Sheet | 核心内容 |
|---|---|
| `01_视频总览` | 账号、video_id、源文件、时长、视频/ASR/AI 状态、涉及书籍、主题、重复簇、证据路径 |
| `02_带货脚本拆解` | Hook 原话与类别、故事、受众痛点、Bridge 原话与时间、CTA 原话与时间、价值锚点、输入模式 |
| `03_视觉模板` | 4 张关键帧的路径及时间、画面形式、字幕风格、书籍露出、深度样本补帧信息 |
| `04_账号对标与高频规律` | 6 账号视频数量、各类高频主题/书籍、重复开头、跨账号复用、CTA/Bridge 类型差异和证据视频 |
| `05_原创带货模板库` | 3～8 套有证据的原创结构模板、适用场景、参考 ID、建议原创选题与风险 |
| `06_异常待复核` | 无语音、无法解析、ASR 不可靠、书名歧义、AI 缺证据、失败记录、待授权/待处理 |
| `07_口径与运行摘要` | 账号与文件数量核对、重复/唯一口径、成功率、工具版本、运行时长、处理成本、状态定义 |

**Excel 要求**：浅蓝简洁样式，冻结表头、开启筛选、列宽合理、证据路径可点击；超长全文保存在 TXT/JSON，Excel 放摘要/链接；原始外部文本必须防范公式注入。聚合数字须可追溯至 video_id；不允许 AI 虚构互动指标。

## 5. 工作目录与交接契约

```text
<OUTPUT_DIR>/
  README.md
  manifest/manifest.jsonl
  state/<video_id>.json               # Codex 独占写入
  transcripts/<video_id>.txt           # Codex 独占写入
  segments/<video_id>.json             # Codex 独占写入
  frames/<video_id>/*.jpg              # Codex 独占写入
  clusters/                            # Codex 独占写入
  handoff/<video_id>/                 # Codex 打包，最后写 READY.json
    input.json
    transcript.txt
    frames/*.jpg
    original_video.path.txt           # 仅供授权后选择可读的原视频
    READY.json
  analysis_a/<video_id>.json           # A 独占写入
  analysis_a/account_summary.json     # A 独占写入
  reports/
  阅见生活_竞品视频分析_终版.xlsx
```

**`input.json` 最少包含**：`video_id`、`account`、`duration_s`、`transcript_path`、`frames`（实际时间与路径）、`source_video_path`、`schema_version`、`ready_at`。  
**`analysis_a/<video_id>.json` 最少包含**：`video_id`、`input_mode`、`analyzed_at`、`fields`、`evidence`、`limitations`、`status`、`schema_version`。  
**状态值**：`DISCOVERED / LOCAL_RUNNING / LOCAL_OK / LOCAL_FAILED / HANDOFF_READY / AI_PENDING / AI_OK / AI_REVIEW / COMPLETE`。这些状态可根据实现细化，但任何 `FAILED`、`PENDING` 不得冒充 `OK`。

## 6. 验收表（Codex 必须提供证据）

| 验收项 | 合格门槛 | 核验方式 |
|---|---|---|
| 完整盘点 | 源目录中支持的视频文件**100%**进入 manifest；约317条只是待核实记录 | 按账号统计与文件系统数量核对 |
| 不破坏源素材 | 无删除、覆盖、重命名、移动；抽样文件 SHA-256 前后一致 | 日志与抽样哈希 |
| 样本质量 | 10 条覆盖尽可能多的账号；逐条检查开头、重要书名/人名、引书和结尾；问题有明细 | `10条样本验收.md` + 人工点检 |
| 可用转录 | 对**有可辨识语音且可解码**的视频，目标≥95%生成可用文本；无语音单独计数 | 文本非空、抽查对应音频，不以非空等同正确 |
| 有效截图 | 每条可解码视频至少 1 张正确画面；正常时 4 张，记录实际时间 | 对照视频和截图 |
| 聚类可信 | 完全重复/相似口播/相同选题分口径统计；随机人工检查至少20对（不足则全查） | 检查误合并与视频 ID 证据 |
| A 的模态可信 | 2 条 MP4 音画理解验证记录；失败则使用文本+截图且不冒充原视频分析 | 提问、对照视频、`input_mode` |
| A 的结果可信 | 每个 `AI_OK` JSON 满足 Schema，Bridge/CTA 等关键结论有真实原文或时间证据；未知留空 | Codex JSON 校验 + 抽查 |
| 深度样本 | 推荐 20～30 条（素材不足或额度限制可注明实际值），需理由及多样性 | 候选报告及覆盖分布 |
| Excel | **一个 7-Sheet 文件**；视频总览与 manifest 一致；链接可用；汇总可追溯 | 程序校验 + 人工打开检查 |
| 断点续跑 | 中断后 `--resume` 不重做已完成步骤；失败有错误日志、有限重试 | 实际模拟中断与重复执行 |
| 权限与费用 | 未经用户同意上传素材数 = 0；不私取登录凭证，不调用未授权收费 API | 日志与用户授权记录 |

**终验状态只能写**：`PASS`（达到上述目标）、`PARTIAL`（部分完成，列出缺项）、`BLOCKED`（缺目录、样本未通过、权限或输入方式不可用）。最终汇报必须注明实际视频数、本地成功数、AI 深度完成数，不能统称为“317 条全部分析完成”。

## 7. 极简操作流程（给用户）

1. **只启动 Codex**：提供本计划书和下载目录绝对路径，要求先做 Phase 0～1。
2. Codex 报告 `10条样本验收.md` 后，核对书名、人名及素材安全。与此同时在 A 里测试 2 条 MP4 是否真能看懂声音和画面；确认可向云模型发送哪些素材。
3. **确认 G1 后**让 Codex 继续全量本地处理；给 A 发送本计划书第 8 节指令和共享输出目录，让 A 先做 3～5 条试标注。两者并行，但不抢写同一文件。
4. 等 Codex 的高频复用报告与 20～30 条候选清单出来后，让 A 逐批做正式深度分析；每批写回 `analysis_a/`。
5. A 完成或达到当前额度后，**最后让 Codex**导入 JSON、生成 Excel、执行完整 QA、交付最终报告。

不要求额外云 API、不要求自建服务，也不要求用户手工逐条复制 317 份文案。若当前 Antigravity 无受支持的自动批处理入口，A 的工作可按批次交互处理，用户只需在关口确认及必要时发起下一批任务。

## 9. 项目成功的判定

**不是“采集了很多字段”，而是能回答三个业务问题：**

1. **哪些题材值得测？** 有具体书名、受众、开头结构及跨账号复用依据，同时注明尚无销量证据。
2. **为什么值得测？** 可以在真实文案或画面中定位 Hook → 故事 → Bridge → CTA，而非空泛总结。
3. **怎样原创生产？** 至少有若干可执行的脚本结构，能直接交给 GPT/Gemini 写原创文案、再交给现有剪映自动化，不必重新阅读所有竞品视频。

**最终决策：先执行 Codex 的 Phase 0～1；A 只需在有样本后接入，二者中途并行，最后 Codex 统一验收。**
