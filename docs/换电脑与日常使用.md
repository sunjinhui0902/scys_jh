# 换电脑与日常使用

本项目面向 Windows 10/11。知识库与代码可以直接阅读；视频下载器、剪映草稿和随包工具以 Windows 为目标。首次安装与从 GitHub 恢复需要联网，账号需要在新电脑重新登录。

## 第一次取回项目

在新电脑安装 Git、GitHub CLI（可通过 Windows 的 winget 安装）：

```powershell
winget install --id Git.Git --exact
winget install --id GitHub.cli --exact
```

重新打开终端，登录并取回仓库（仓库现已公开，推送仍需账号权限）：

```powershell
gh auth login --web --git-protocol https
gh auth setup-git
gh repo clone sunjinhui0902/scys_jh
cd scys_jh
```

双击 `新电脑初始化.bat`：安装/检查 Git、GitHub CLI、Python 3.10，创建独立环境，安装固定版本的基础依赖，恢复创作素材和软件下载器，生成本机配置并检查环境。它会修改本机软件安装状态，只需在新电脑准备环境时运行；日常使用运行 `工作台.bat`。

如果没有 winget，可从 [Git](https://git-scm.com/download/win)、[GitHub CLI](https://cli.github.com/)、[Python](https://www.python.org/downloads/windows/) 官网安装，然后运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1 -RestoreAssets
```

基础环境使用 Python 3.10。剪映、微信、Codex 桌面端等需要分别安装并登录，无法靠复制仓库迁移账号或安装状态。字体已保存原有文件，但使用范围仍取决于原字体许可。

## 大文件在哪里

文案、知识库、表格、分析 JSON、字幕、脚本和项目技能在 Git 中；创作工程的成片、配音、截图、字体和第三方软件放在**同一个公开仓库**的 [Releases](https://github.com/sunjinhui0902/scys_jh/releases)。

`config/bundle-manifest.json` 记录每个文件的原相对路径、大小、SHA-256、所属分组及恢复分卷。相同内容只存一次，恢复时恢复每个原文件名。分卷小于 GitHub 每附件 2 GiB 限制；恢复检查分卷和文件哈希，已有同哈希文件会跳过，不同内容会停止并保留本地文件。

| 分组 | 内容 | 默认恢复 |
|---|---|---|
| core | 已有视频工程、成片、配音、字体和视觉素材 | 是 |
| software | 既有 DouK、wx_channel、FFmpeg 及附属运行文件 | 是 |
| analysis | 分析关键帧、联系表和结果配图 | 否，按需 |

```powershell
# 只恢复分析结果配图
.\.venv\Scripts\python.exe scripts/bundle.py restore --group analysis
# 恢复所有内容（需要足够磁盘和下载时间）
.\.venv\Scripts\python.exe scripts/bundle.py restore --group all
# 恢复全部结果，并按需安装历史语音识别依赖
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1 -Full -Analysis
```

**按用户要求，采集原始视频、提取音频和本机模型缓存不上传；全部恢复只包含结果与开发素材。** 原视频仍留在旧电脑，分析报告、文案、转写与字幕保留。

语音识别依赖另存于 `requirements-analysis.txt`；旧机原始版本清单为 `requirements-analysis.snapshot.txt`。旧机 Torch/Torchaudio 版本不配套，新安装配置已将两者配对为 2.11.0；这部分尚未在全新环境完成整套模型转写验证。基础视频创作环境与可运行的渲染示例已单独验证；新一轮 ASR 应提供新的源视频、重新下载模型并重建输入清单，不能直接依赖旧审核状态。

## 日常跨电脑同步

开始前双击 `同步_拉取.bat`；结束时双击 `同步_保存推送.bat`。脚本检查约定的公开状态、凭据误提交和冲突。多台电脑不要同时编辑同一个工程。遇到远端分叉会停止，交给 Codex 保留双方内容后处理。

**日常推送只同步 Git 中的资料和代码。** 新建/修改的 mp4、图片、音频及其他被忽略的媒体，不会随普通推送上传。需要一起换机时，让 Codex 更新恢复包，或执行：

```powershell
.\.venv\Scripts\python.exe scripts/bundle.py pack --tag workspace-YYYY-MM-DD-v2 --upload
```

使用全新 tag。全部附件上传成功后，将新的 `config/bundle-manifest.json` 提交推送，再发布该草稿 Release，并将 tag 指向包含新清单的提交。旧版本不覆盖，因此可以按旧版本恢复。上传中断时保留本地分卷，核对 Release 中已存在附件后补传；不强制替换同名附件。

## 竞品分析接续

每次先读 [竞品分析协作总控](竞品分析协作总控.md) 与其机器状态，按最新批次继续。每批结束由Codex更新总表、报告、文库索引、总控及追加日志，再同步本任务结果；A不得覆盖已验收批次。

## 继续视频开发

1. 先看 `05_爆款知识库与复盘/README.md` 和 `竞品视频分析_2026-10-15/content_library/开始使用.md`，选择下一条原创选题。
2. 在 Codex 中打开仓库根目录，项目技能位于 `.agents/skills/`，无需复制个人的整个技能目录。可说“用 scys-workspace 检查工作台”，或调用 `$wechat-channels-book-commerce`。
3. 复制 `config/storyboard.example.json`，调整相对路径、镜头和时长，运行：

```powershell
.\.venv\Scripts\python.exe scripts/render.py config/storyboard.example.json --output .local/示例预览.mp4
```

该示例使用现有配音和两张图片生成 6 秒竖屏预览；可以在 JSON 中加 `subtitles` 字段指定 SRT。完整成片的文案、事实与商品信息按实际选题调整。旧流水线在 `04_自动化生产流水线/`，保留原来的具体视频内容，未作为通用端到端流水线承诺。

## 历史路径与证据

旧报告、Excel 和分析清单中的 `D:\fuye` 是历史记录。`scripts/relocate.py` 默认生成 `.local/relocated/` 下的本机路径副本，便于查看，不修改原始记录。运行历史脚本前可执行 `--activate` 将 JSON/JSONL 路径替换为本机路径（会产生 Git 差异，原文件备份在 `.local/before-relocation`）。恢复会保留备份中记录的文件修改时间，便于原流水线核对输入；迁移仍应检查文件哈希，不能直接把旧审核状态当作新一轮运行结果。

不应上传 cookie、密钥、机器专属证书、登录二维码、机器指纹、个人 OAuth 状态；新机重新授权。下载器首次运行所需微信证书/系统代理由该工具在新机提示；第三方软件可用性取决于平台和版本，打包不保证绕过登录、授权或运行条件。
