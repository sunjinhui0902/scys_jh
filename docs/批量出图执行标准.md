# 批量出图标准流程

更新：2026-10-21。适用于按镜头清单生成的竖屏AI素材。归档程序为 `scripts/image_batch_pipeline.py`，会话调度入口为 `scripts/image_batch_dispatch.js`。

## 固定约定

- 每批一个全新目录；镜头数量由配置决定，不固定为22张。提交前绑定 `shot_01`、`shot_02` 等编号，严禁按返回顺序编号。
- 单条最终Prompt原样传入内置生图工具，不再自动附加人物、风格或无人物过滤词。结果仍需目检文字痕迹、人体结构和主体构图。
- 会话侧默认3个请求在途，可设置4个；完成一个立即补位。归档在独立队列逐张进行，不占用生成槽位。客户端并发不保证服务端同量并行渲染。
- 使用内置生图能力，不因“批量”切换到付费API或另建SDK生图程序。本地程序只接收工具已经返回的文件。
- AI交付尺寸1080×1920；原生图另存。原生长宽比相对9:16偏差不超过1%时做轻微裁切和尺寸规范化；超过容差报错，不能擅自大幅裁切主体。
- `book_01.png`～`book_03.png`在初始化时从明确配置的固定文件复制，保持字节与原始尺寸。换商品时要更换配置；三张素材的性质依来源区分，不一概声称为实拍。
- 同编号重复回传同一原图可跳过；不同结果、旧请求结果和重复提交均有状态检查。封包前必须全部镜头成功、书图与交付图校验一致。
- 原始图按版本保留，验收封包后冻结。修订在新批次执行，不能覆盖已验收批次。

## 1. 准备配置和固定书图

复制 `config/image-batch.example.json` 为本次配置，替换所有 `REPLACE_` 占位Prompt。未填完时程序拒绝初始化。`shots`按文案顺序连续编号，想做22张就提供22条；Prompt不经过程序改写。

书图的 `source` 相对于**配置文件所在目录**解析，不相对于运行目录。模板引用昨天已经确认的《大美中国》素材，避免依赖临时剪贴板文件；换电脑先从恢复包取回对应文件。

```powershell
.\.venv\Scripts\python.exe scripts/image_batch_pipeline.py init --config "config/本次出图.json" --run-dir "03_视频成片与工程/本次项目/出图批次_01"
```

初始化立即复制三张书图、冻结镜头编号与Prompt、建立可续跑状态。已有目录不会重新初始化。未提供本次清单时不要擅自生图。

## 2. 在会话里启动滑动窗口

以下是供Codex在 `functions.exec` 中执行的入口，不是让用户在终端调用生图工具。初始化后只需改变 `runDir`。工作区根目录动态取得，不在代码中写个人盘符或用户名。

```javascript
// @exec: {"yield_time_ms": 120000, "max_output_tokens": 1500}
const source = await tools.exec_command({
  cmd: "$batchSource = Get-Content -Raw -LiteralPath 'scripts/image_batch_dispatch.js'; @{ repoRoot = (Get-Location).Path; source = $batchSource } | ConvertTo-Json -Compress",
  max_output_tokens: 10000
});
if (source.exit_code !== 0) throw new Error("Cannot load dispatcher");
const loaded = JSON.parse(source.output);
const launch = new Function("tools", "generatedImage", "text",
  loaded.source + "; return runImageBatchInCodex;")(tools, generatedImage, text);
const report = await launch({
  repoRoot: loaded.repoRoot,
  runDir: "03_视频成片与工程/本次项目/出图批次_01",
  concurrency: 3
});
text(report);
```

每个生图请求都被等待到结束；不以未等待的后台Promise代替完成。返回结果只取工具明确提供的保存路径，不打印图片Base64、不猜测“目录里最新的文件”。工具返回格式发生变化时保留已归档结果并停止相关镜头。

归档期间后续生图继续补位；所有生成和归档都结束后，程序才自动封包。中途有失败时完成其余请求并保留成果，最后报未完成，不生成貌似完整的ZIP。

## 3. 失败与中断后续跑

查看每个镜头当前状态：

```powershell
.\.venv\Scripts\python.exe scripts/image_batch_pipeline.py plan --run-dir "03_视频成片与工程/本次项目/出图批次_01"
```

只存在已明确失败的初版请求时，运行 `resume` 重置失败项；已归档镜头保留。若有中断的在途请求，先确认原调用已经停止，再使用 `resume --reset-inflight`。重新运行会话调度入口，只提交未完成镜头。不得为了续跑重新初始化或清空目录。

修图单独登记：

```powershell
.\.venv\Scripts\python.exe scripts/image_batch_pipeline.py start-repair --run-dir "03_视频成片与工程/本次项目/出图批次_01" --shot-id shot_05
```

记录返回的 `attempt`，随后由会话调用内置图片编辑工具。工具返回时立即记录UTC时间，然后使用 `ingest --shot-id shot_05 --attempt <返回值> --source <工具明确返回的文件> --received-at <返回时刻>` 归档。失败使用 `fail` 记录稳定错误码，不保存可能含凭据的原始服务错误。

未完成修图必须显式选择 `retry-repair --shot-id shot_05` 或 `restore-selected --shot-id shot_05`。前者返回新attempt，后者选择上一个已归档版本；不能将修图失败自动当成通过。

## 4. 交付物与计时

| 位置 | 内容 |
|---|---|
| `images/shot_XX.png` | 按镜头绑定的1080×1920交付图 |
| `books/book_01.png`～`book_03.png` | 保留原始字节和尺寸的书图 |
| `originals/shot_XX_vNNN.png` | 每次采用结果的原生图，不覆盖旧版 |
| `preview.jpg` | 编号缩略总览，选图用 |
| `prompts.json` | 按镜头保存的原始Prompt |
| `manifest.json` | 交付文件的尺寸、大小和SHA-256清单 |
| `images.zip` | 图、书图、预览、Prompt和manifest；不重复压缩PNG/JPEG |
| `zip_sha256.txt` | ZIP校验值 |
| `timing.json` | 完整计时，ZIP校验结束后生成，放在ZIP旁边 |
| `state.db`、`thumbnails/` | 续跑状态和中间缩略图，不是主交付物 |

`timing.json`必须在最终ZIP完成校验后落盘，因此不纳入它所计时的ZIP，避免循环计算。ZIP逐文件SHA-256核验通过后才宣布交付。

| 固定输出 | 起止口径 |
|---|---|
| `[T1: 初版出齐耗时]` | 首个生图提交登记 → 所有镜头的首个有效初版返回 |
| `[T2: 修图耗时]` | 首次修图提交登记 → 最后修图返回或被明确取消；无修图为0 |
| `[T3: 归档打包耗时]` | 最后一张最终采用图返回 → ZIP生成、CRC与SHA-256校验完成；目标低于60秒 |

T1和T2可能重叠，不能直接相加当作总耗时。T3包含最后结果返回后仍未完成的归档队列，不能只计压缩时间。另报 `total_to_local_seconds`，从批次初始化到本地交付完成；其中不包括配置准备之前的对话时间。整轮任务耗时还应从用户任务开始另计。

云端备份按既有 `scys-workspace` 和项目恢复包规则进行，不计入T3；实际上传和核验后，可使用 `record-backup --started-at <开始时刻> --finished-at <核验结束时刻>` 记录，并报告含备份的总时间。程序不会自行上传素材。

人工检查需要返工时应在最终封包之前登记修图。已经封包的批次冻结，不能先宣称验收通过再静默覆盖图片。

## 与剪映工程配合

这套程序只处理图片素材，不替代 `scripts/fast_draft_pipeline.py` 的工程装配流程。有已确认口播和分镜的实际视频任务，生图期间仍按项目约定并行初始化草稿。将本批按镜头编号选定的图片复制到该工程的 `02_分镜视觉素材/` 后，使用既有 `apply-images` 入口；不得将图片归档完成直接称为成片验证通过。

## 验证与当前边界

### 多集共用一个批次

`shots`仍使用批次内连续编号；每条可配置仓库相对路径`delivery_path`，例如`03_视频成片与工程/某单集/assets/shot_02.png`。归档时自动复制到该镜头位置，不按生成返回顺序命名。发生已登记重出时，旧副本移至该集`assets/revisions/`。

可选`delivery_slots`逐项声明`project`、`shot`、`target`、`kind`。`generated`项指定`generation_id`；`book`和`reuse`项指定仓库相对`source`。复用源应先于引用项装配。每张新图必须且只能绑定一次；封包复制完整分集目录和各集预览、清单。实例见`03_视频成片与工程/五城精讲_出图清单_2026-10-21.json`。

长清单必须校验待出、在途、失败和已归档数量之和等于总数。会话适配器对清单返回预留较大输出空间，识别截断即停止提交，不能根据残缺清单继续生图。

仅备份本批创作图片时，使用`bundle.py pack --tag <新版本> --core-prefix <单集assets目录> --core-prefix <批次目录> --upload`，可重复提供目录。只收PNG/JPEG/WebP并保留历史包引用；不重新扫描全仓库音视频。

2026-10-21五城实测：39张不同AI图，装配60个镜头；T1为2313.203秒，T2为147.358秒（1次重出），T3为24.610秒。本地交付从初始化计2428.414秒。曾因清单输出截断导致漏派及1张错图，现已补齐、重出并加入阻断校验；该次结果不能作为无返工的理想吞吐量。
